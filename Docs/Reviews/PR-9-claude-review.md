## Non-blocking notes

1. **One prompt, not two.** The focused interactable's prompt takes priority and the held action's prompt appears only when no target prompt is visible (a test pins this). `INTERACTION_SYSTEM.md` §3.1 asks for both lines; with a bag in hand and the player looking at a station, "[F] Open / Shake" would be hidden. Resolve in the integration branch by adding a `HeldQuery` to `InteractionPromptChanged` (additive; subscribers only read properties) and showing two lines.
2. **A hold cancels on any query change**, including the prompt key (a test, case `action`, pins it). That is a reasonable rule — the prompt key is the action's identity — but it must be documented, and no hold-capable interactable may change its prompt key mid-hold. Now written into §3.1.
3. **Held use is Press or Hold only.** `IHeldItemAction` has no release callback for `Continuous`; a held-only action that returned a `Continuous` query would start and never complete. Make `BeginHeld` ignore (and report) a `Continuous` held query, with a test.
4. **Esc freezes; losing application focus or disabling the interactor cancels.** Defensible, and tested, but narrower than "pause freezes". Now written into §3.1.
5. **Hard-coded `[F]`** in `InteractionPromptView` while the target prompt key comes from the table: add a table entry (for example `[F / RMB]`).
6. **`ActionBlocked`** for a held-only action (no `IInteractable`) carries an invalid `InteractableId`; acceptable, but a QA log cannot say which item.
7. **Rebase onto `develop`** so the squash does not carry PR #7's commit.
